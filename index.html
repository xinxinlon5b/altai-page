序章 · 起点

这要从"旧时代的我"说起

在做这个项目之前，我的交付方式是另一套 —— 而这次，我把自己的老路子彻底打碎了。

🕰️ 旧模式 · 我以前的交付

  • 开着远程软件（向日葵/TeamViewer），一个软件一个软件地帮客户手动安装
  • 装一个 agent + 给几个 skill 就算交付完成
  • 客户装完，我远程盯着，出了问题再回来修
  • 安装过程全靠我肉眼盯，全英文界面，客户看不懂
  • 收 2k–8k，靠的是"我亲手帮你装"的苦力钱

🚀 新模式 · 这次的交付

  • 客户电脑全新裸机，我用 IP 远程 + SSH 命令行 全程接管
  • 一个 v1.0.2 一键交付包 解压即装，43 项验收自动跑
  • 安装进度实时动态看板，客户自己都能看到跑到哪了
  • 中文可视化进度 + 小白安装 PPT + 说明书，不靠人肉盯
  • 安全内核 100/100，可复制、可复用、可定价 —— 企业级
💡我的原话：「我觉得我们这种安装的方式太酷了，又专业，你又能及时发现问题解决问题，这可比我开远程给对方一个软件一个软件的装，体验感好太多了」

08-08 · 21:41 阶段 1 · MVP 起点 动机：验证可行性

第一句话：这是一次"好实现吗？"的试探

💬 我说的
客户是做跨境电商的，经常从 VK 获取信息。他们分主动获客（爬信息→私聊→WhatsApp 聊）和被动获客两种。要做到 24 小时不间断获取信息 + 自动化聊天，好实现吗？去 GitHub 查成熟经验。

我甚至不懂"防滥用机制虫""住宅网络通道"是什么，但我做对了一件事：先问可行性，再决定动不动手 —— 这是标准的 MVP 思维。

🧭为什么：不敢乱烧钱乱试错，先把"这事能不能成"搞清楚，才敢往下走
✅ 确定方向：VK 获客 + 自动化私聊✅ 明确要 24h 不间断
08-08 · 深夜 阶段 2 · 规则先行 动机：怕伤害客户

"先别跑，规则得先立好" —— 1.0 对话规则诞生

💬 我说的
你一定要有一个 1.0 规则，和对话的规则。不然没有规则和理由，成功率不高，还伤害客户，有可能会被投诉。跟谁对话、回复什么，都要有清晰规则和理由。

当天晚上我连续加了 5 个想法：对话规则、平台规则（防投诉/防限流）、在 Obsidian 建工程每天更新、做成"真项目"（目标+SOP+验收标准）。小白的第一直觉，反而成了企业级的种子。

🛡️为什么：没规则乱发 = 砸客户招牌 + 被投诉限制，规则是获客的生命线
✅ 话术规则 1.0✅ VK 平台合规研究✅ Obsidian 工程化✅ 项目 SOP + 验收标准

08-10 · 下午 阶段 6 · 精聊 + 画像 + 迭代 动机：像活人一样聊天

"像钓鱼一样获客" —— 深度画像与话术每日迭代

💬 我说的
主动开拓的客户，广告性质弱一些、生活气息多一些，像钓鱼一样。我希望你去爬目标客户账号的更多信息（发布内容/图片/文字），让我们更有活人感、更有针对性，找到对方痛点。话术体系每天迭代，直到最优版本。

这是我产品思想最密集的一天，一口气加了 6 个规则：精聊（弱广告）、深度画像、话术日更、对话边界（什么情况不再回复 + 祝福式结尾）、意向客户建群、发消息前给筛查报告。一个不懂技术的人，把"获客"想成了"交朋友"。

🎣为什么：硬广=被拉黑投诉；有温度有针对性=对方觉得你是真人，才愿意聊

08-13 阶段 10 · 远程交付革命 动机：告别手动安装

全新电脑、IP 地址授权、一次性远程连接我的 agent 完成安装 —— 为 1 对多电脑多系统做准备

💬 我说的
从前的我是开着远程软件/视频帮人一个一个手动安装调试。今天我第一次尝试：用电脑的 IP 地址授权，一次性远程通过连接我的 agent 来完成高效安装，对面是全新裸机，啥都没装也能远程装。你设定心跳模式全程完成安装测试调度，过程要让客户看得见（GUI 跑）。我还让你做了小白安装 PPT 和说明书 —— 每一句该和 agent 说的话都写进去。这也在为以后 1 对多电脑、多系统（Mac / 鸿蒙 / Windows）同时安装做准备。

🖥️为什么：手动远程装 = 累死 + 客户干等 + 出问题我看不见；IP 命令行 + 看板 = 专业、透明、可远程排障

08-15 · 下午 阶段 20 · 回传网络代码登录 动机：对方电脑登不了账号，换个思路照样进

对方电脑无法登录账号 —— 用"回传网络代码"的形式，在我这边登录成功

💬 我说的
而且对方电脑无法登录账号，我们是用了新的方法——回传网络代码的形式，在我这边登录成功的这个经验也非常宝贵。这个方法和流程要一起记录进去。

异地组网时遇到硬骨头：对方电脑（河南 IP）登录 Google 账号被拦——Google 安全系统检测到"同一账号在长春登录后，又从河南登录"= 异常登录，卡在验证页进不去。解决办法不是死磕对方浏览器，而是换个思路：登录链接回传。① 对方机器跑 Tailscale 登录命令 → 生成一个一次性授权链接；② 把链接回传到我这边；③ 我在本机浏览器打开（本机 Google 会话本来就有效）→ 一键授权；④ 对方机器自动完成登录、进入同一个虚拟网络。妙处在于：登录动作永远发生在"信得过的那台机器"上，对方那台只是拿授权结果——以后任何"对方登不了账号"的场景（异地 IP 平台规则、验证码、2FA）都能用这招规避。

🔐为什么：对方电脑在异地，Google/平台平台规则会拦截"异地登录"；回传链接 = 把登录动作搬回主控本机，既安全又高效 —— 这是远程装机里最巧的一手
